# 실행 로직 2차 수정: 사용자 예제 기반 함수 검증

이 문서는 2차 수정 당시의 기록입니다. 현재 검증 방식은 [범용 검증·통합 검사·복구·중단/재개](UNIVERSAL_VERIFICATION_AND_RECOVERY.md)를 참고하세요. 아래의 계산기 전용 예제 추출·추가 연산 생성은 범용 검증 계약으로 교체되어 현재 실행 경로에서는 사용하지 않습니다.

## 변경 흐름

요구사항 분석 → 대표의 분석 확인 → 코드 작성 → 문법·금지 조건 검사 → 지원 함수 예제 검사 → AI/규칙 QA → 필요 시 재작업 → 저장 파일 재검사 → 대표 최종 승인.

화면 배치·스타일·메뉴와 기본 모델 설정은 변경하지 않았다.

## 사용자 예제를 합격 기준으로 사용

모델이 임의로 만든 답을 정답으로 사용하지 않는다. 원래 요구사항의 예제를 추출하고, 계산기에는 수학적으로 확정되는 추가 연산을 별도로 넣어 분석 화면의 합격 기준과 작업 계약에 표시한다.

- 일반 함수: `add(2, 3) = 5`, `convert(10) -> 20`처럼 리터럴 인자와 예상 결과를 지정한다.
- 수식 함수: `calculate(expression) 함수`처럼 인터페이스를 지정하면 `2+3*4=14`, `(2+3)*4=20` 같은 예제도 연결한다.
- 이번 계산기 요구사항에서는 정상 계산 5개와 `1/0`, `2+` 오류 처리 2개를 추출했다.
- 여기에 `7+8`, `9-12`, `6*7`, `0/2`, `(8-2)/3`의 독립 연산 5개를 추가한다. 예제 답만 하드코딩해도 합격하지 않도록 검사한다. 유한한 테스트가 모든 입력의 정확성을 보장하는 것은 아니다.
- 함수는 파일 최상위에 노출하며 GUI 생성·표시 로직과 분리한다. GUI는 그 함수를 호출한다.
- 테스트 파일을 지정하지 않은 여러 Python 파일 요청은 파일별 검사 대상을 추측하지 않고 미검증으로 표시한다.

## 검증 방식과 범위

생성 파일을 import하거나 exec/eval로 실행하지 않는다. 별도 Python 프로세스에서 신뢰된 제한 AST 해석기가 지정된 함수와 필요한 상수·헬퍼 함수만 해석한다. 메인 가드나 GUI 시작 코드는 실행하지 않는다.

지원 범위는 순수 함수의 기본 연산·분기·반복·내부 함수와 일부 `ast`, `operator`, `math`, `re`, `collections` 기능이다. 네트워크·파일·프로세스 접근이나 사적인 객체 속성 접근은 제공하지 않는다. 생성된 코드가 검증기의 제한을 우회해 Python 전체 기능을 호출하도록 허용하지 않는다.

- 정상 사례의 실제 결과가 다르거나, 요청한 함수가 없거나, 오류 처리 사례가 정상 숫자를 반환하면 FAIL.
- 지원하지 않는 언어 구조·외부 의존성이 필요하면 NOT_RUN. 통과로 간주하지 않는다.
- 계산 단계 30,000회, 함수 호출 깊이 80, 예제 32개, 값 크기와 소스 크기 제한, 프로세스 시간 제한을 둔다.
- 이는 Python 전체 실행기나 OS 샌드박스가 아니다. AST 해석의 지원 범위 밖은 수동 실행 검증이 필요하다.

## QA와 승인 연결

함수 예제가 실패하면 모델 QA를 기다리지 않고 입력·예상값·실제 결과를 재작업 지시로 전달한다. 요구사항의 예상값을 수정하거나 입력별 답을 하드코딩하지 못하도록 지시한다. 저장한 파일에도 검사를 다시 적용하며, 최종 결과에는 파일별·예제별 상태가 표시된다.

수식 예제별 상수 반환만 있고 일반 계산 경로가 없는 명백한 구현은 정적 검사에서도 거부한다. AI QA에는 예제 통과만으로 일반 파서 요구사항을 완화하지 않도록 명시한다.

최신 QA가 실패하면 기존 승인 대기를 자동 무효화(INVALIDATED)한다. 승인 직전에도 같은 결과가 최신 QA를 통과했는지 트랜잭션 안에서 다시 확인한다. 승인 화면에는 과거 통과 기록보다 최신 재검증 실패를 먼저 표시한다. 이미 승인된 기존 사용자 결과를 자동 취소하는 변경은 아니다.

함수 예제가 통과해도 프로그램 전체 시작·GUI·키보드 동작·다른 기능이 검증된 것은 아니다. 전체 실행은 별도 NOT_RUN으로 남기며 대표 확인을 유지한다. 함수 검사 자체가 NOT_RUN이면 AI가 PASS로 답해도 PASS_WITH_WARNING으로 표시한다.

## 추가 보완

- 프롬프트의 현재 작업 지시가 Context에도 중복되어 모델 입력을 낭비하던 부분을 제거했다. 선행 작업 인계는 유지한다.
- eval/exec 금지 위반과 계산 결과 실패에 대해 각각 다른 수정 전략을 전달한다.
- 모델별 설정은 그대로 지원하며 특정 모델 이름에 따라 프로그램 로직을 바꾸지 않는다.
- 개별 실행에서 제공자별 옵션을 명시할 수 있게 했다. 사고 과정 옵션을 모델 이름만 보고 자동 설정하지 않는다.
- 승인 전 분석 계획이 요청하지 않은 파일을 추가하는 등 유효하지 않으면 원래 요구사항 범위로 규칙 기반 계획을 다시 구성하고, 그 사실과 원인을 표시한다. 클라우드 승인 조건은 그대로 보존하며, 이미 확인된 분석을 실행할 때는 여전히 잘못된 파일 배정을 거부한다.

## 실사용 재시험

`scripts/run_calculator_verification.py`는 데스크톱 화면과 같은 백엔드로 분석·작성·QA·검증을 실행한다. 이 테스트에서는 대표의 분석 확인 단계를 자동 수행하고 최종 승인은 수동 대기로 둔다. 생성 프로그램 전체를 자동 실행하지 않는다.

```powershell
.\.venv\Scripts\python.exe -u -B scripts/run_calculator_verification.py
```

모델·시험 옵션을 명시하는 비교 시험도 가능하다. `--no-thinking`은 Ollama 서버가 해당 모델의 thinking 지원을 보고한 경우에만 전송하며, 기본 설정 파일을 바꾸지 않는다.

```powershell
.\.venv\Scripts\python.exe -u -B scripts/run_calculator_verification.py --model gemma4:12b --timeout 600 --no-thinking
```

기본 gemma4:e2b 시험(PRJ-F0128661)은 eval 금지 위반 2회와 닫히지 않은 artifact 1회로 차단됐다. 두 완성 응답의 종료 사유는 stop이므로 이 두 실패를 단순 출력 한도 초과로 단정할 수 없다. 지원 모델도 요구사항을 반드시 지킨다고 보장할 수 없으며, 실패를 자동 검증으로 차단하는 것이 필요하다.

gemma4:12b 비교 시험은 분석에서 요청에 없는 logic.py를 추가하려 하여 당시 계획 검사에서 중단됐다. 이 관찰을 반영해 승인 전 계획 복구를 추가했다. 12b의 프로그램 전체 작성 성공을 확인한 시험은 아니다.

보완한 지시와 thinking 비활성화 옵션을 사용한 gemma4:e2b 시험(PRJ-686AF56B)은 예제 7개를 통과하고 AI QA도 PASS를 반환했다. 그러나 실제 코드는 예제 정답을 하드코딩하고 있었다. 독립 연산 5개를 추가해 재검증한 결과 5개 모두 FAIL이었다. 해당 시험의 승인 대기는 INVALIDATED, 프로젝트는 BLOCKED로 변경했다. 생성 파일은 성공 산출물로 간주하면 안 된다. 원래 실행 기록은 보존하고 `projects/PRJ-686AF56B/revalidation_result.json`에 후속 검증을 별도로 기록했다.

동일 요구사항의 이전 분석을 재사용하는 시험 옵션 `--reuse-analysis <기존 시험 JSON>`도 추가했다. 저장된 프로젝트 요구사항이 정확히 일치할 때만 재사용하며, 시험 결과에 출처를 기록한다. 위 비교는 모델·옵션·지시 보완이 함께 달라졌으므로 모델 자체 성능의 통제된 비교 실험으로 해석하지 않는다.

최신 실제 시험 결과: `CALCULATOR_RETEST_RESULT.json`. 시험별 기록: `calculator_retests/`.

## 회귀 테스트

```powershell
.\.venv\Scripts\python.exe -B -m unittest discover -s tests -v
```

기존 흐름 외에 정상/오류 예제, 틀린 계산의 재작업, 지원하지 않는 코드, 무한 반복·과도한 값, 파일·네트워크·객체 접근 시도, 예외 처리로 검증 제한을 숨기는 시도, Python 기본 호출 의미 등을 검사한다. 실제 모델 출력의 품질 검증은 위 실사용 시험과 구분한다.

최종 회귀 테스트 57개 통과. 전체 앱/시험 스크립트 문법 검사와 운영 DB의 읽기 전용 무결성 검사도 통과했다. 시험 프로젝트 PRJ-686AF56B의 최종 현재 상태는 BLOCKED, 승인 상태는 INVALIDATED이며, 기본 모델 설정은 gemma4:e2b로 유지됐다.
