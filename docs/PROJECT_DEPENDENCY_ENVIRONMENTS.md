# 프로젝트별 의존성 환경 — 2026-10-27

요구사항 분석의 `library_requirements`에 패키지 이름, 런타임, 사용 목적, 정확한 버전(선택)을 기록한다. 버전 미지정은 Docker 안에서 해석한 실제 버전으로 잠근다. 버전 범위, URL, 설치 명령어, 로컬 경로는 패키지 입력으로 허용하지 않는다.

## 실행 흐름

1. 분석을 확인하고 작업을 실행하면 `projects/<프로젝트 ID>/environment/`에 의존성 목록을 기록한다.
2. 설치·확인된 기본 Python 이미지에 프로젝트 패키지를 추가한다. 빌드 문맥에는 시스템이 작성한 Dockerfile과 검증된 패키지 목록만 들어간다. 생성 프로그램, API 키, 호스트 프로젝트 폴더는 빌드에 포함하지 않는다.
3. PyPI에서 wheel만 설치하고 `pip check`를 실행한다. 패키지 다운로드 때문에 이미지 준비 단계에는 인터넷 연결이 필요하다. 소스 패키지를 빌드하거나 호스트 pip를 실행하지 않는다.
4. 완성된 이미지에서 네트워크 차단, 읽기 전용 루트, UID 65534, 시간·메모리 제한을 적용해 설치 버전, import, `pip check`를 확인한다.
5. 모두 통과하면 고정 SHA256 이미지 ID를 해당 프로젝트의 QA·통합 검사·최종 저장 파일 검사에만 전달한다. 공용 설정과 다른 프로젝트의 이미지는 바꾸지 않는다.
6. 이후 생성 프로그램은 기존 격리 실행기로 검사한다. 패키지 설치 성공과 프로그램 요구사항 충족 여부는 별도 검사다.

저장 파일:

- `dependencies.json`: 요청 패키지·버전, 실제 설치 버전, 기본/프로젝트 이미지 ID, 준비 상태, 검사 결과 또는 실패 원인·조치
- `requirements.requested.txt`: 분석에서 요청한 직접 의존성
- `requirements.lock.txt`: 설치 검사에 통과한 전체 Python 배포판 버전(기본 이미지의 도구와 간접 의존성 포함)

의존성·기본 이미지·검사 정책이 같으면 기존 이미지를 재사용하되 import와 의존성 검사는 다시 한다. 이미지가 삭제되었으면 저장한 정확한 버전 목록으로 재구성한다. 사용자가 재시도하려면 기존 프로젝트 재검증 명령을 사용할 수 있다:

```powershell
.\.venv\Scripts\python.exe -B -X utf8 scripts/setup_docker_verification.py --project PRJ-XXXXXXXX
```

## 실패 처리 및 지원 범위

패키지 준비 실패 시 원본 Docker/pip 오류와 해결 안내를 저장하고 실행 결과에 표시한다. 다른 공용 이미지나 호스트 실행으로 대체하지 않는다. 필수 `DEPENDENCIES: NOT_RUN` 기록이 남아 자동 승인을 막는다. 정적 검사·코드 작성은 계속할 수 있지만 실행 검증 완료로 표시하지 않는다. 중단 시 CANCELLED를 저장하고 재개할 때 다시 준비한다.

현재 자동 준비 범위는 Python/PyPI wheel이다. Node 등 다른 런타임, OS 라이브러리가 필요한 패키지, 호환 wheel이 없는 패키지, 자동 import 검사 대상을 찾지 못하는 메타 패키지는 별도 검토 환경이 필요하다고 안내하고 미검증으로 남긴다. 이미지 준비 성공이 모든 GUI 기능이나 모든 외부 패키지 지원을 보장하지 않는다. 선언되지 않은 패키지를 생성 코드가 추가로 사용하면 실행 검사에서 실패할 수 있으며 의존성을 재분석해야 한다.

패키지를 내려받기 전 파일 해시를 고정하는 공급망 잠금 기능은 이번 범위에 포함하지 않았다. 정확한 버전과 검증된 로컬 이미지 ID를 기록한다.
