# 업무 배정 지침과 실행 규칙 통일 — 2026-10-26

코드 작성 요청에는 비서실장 프롬프트·분석 결과 정리·실행 단계가 같은 `app/chief/allocation_policy.py` 정책을 사용한다.

- 비서실장: 요구사항 분석, 업무 분장, 결과 취합.
- 간단한 프로그램: 개발 담당자 1명이 구현과 통합을 담당한다.
- 복잡한 프로그램: 기능 의존성, 외부 API/DB 연동, 검증 난이도를 근거로 필요한 역할만 추가한다. 파일 수만으로 복잡도를 결정하거나 분장을 위해 산출 파일을 늘리지 않는다.
- 디자인 담당자는 배정된 UI 파일을 구현할 수 있다. 프론트엔드·백엔드 등 서로 다른 구현 역할은 별도로 유지한다.
- 통합 담당: 배정된 개발 역할 중 정확히 한 명을 `integration_role`로 지정한다. 나머지 담당 산출물 이후 실행하고 선행 작업 모두를 의존성으로 갖는다. 통합 담당의 별도 파일이 없다면 파일을 중복 생성하지 않고 통합 검토와 담당 파일별 수정 지시를 작성한다.
- QA: 고정된 독립 검토 역할이며 구현 파일이나 통합 담당자로 배정할 수 없다. 기존 작업별 QA와 전체 계약 검증을 수행한다.

단순 질문처럼 코드 구현이 필요 없는 요청은 비서실장이 직접 답할 수 있다. 복잡도는 여전히 모델이 위 기준을 사용해 분석하며 숫자 점수로 확정하는 방식은 아니다. 최종 역할·파일 배정은 대표의 분석 확인 단계에서 확인한다.

## 충돌 방지

이전에 발생했던 `Chief of Staff (Self)` 파일 배정은 분석 단계에서 해당 파일·검증 범위를 유지한 채 개발 담당자 배정으로 정리한다. 비서실장이 직접 구현한다는 설명도 정책에 맞게 정리한다. 같은 정책을 실행 전에 다시 적용하므로 분석 확인 데이터를 통해 비서실장 직접 작성을 우회할 수 없다.

QA의 파일 배정, 존재하지 않거나 개발 역할이 아닌 통합 담당자, 중복 파일 소유권은 허용하지 않는다. 기존 파일 경로·산출 범위 검사는 계속 적용된다.

프론트엔드/백엔드 개발자를 일반 개발자라는 이유만으로 합치던 역할 정리와 `DB Specialist`/`Database Specialist`를 별도 인원으로 만들던 이름 중복도 수정했다.
